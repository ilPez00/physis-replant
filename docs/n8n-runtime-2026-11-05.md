# Actual n8n loop and token savings — 2026-11-05

## What ran

- n8n **2.46.5**, real workflow execution using `n8n import:workflow` and
  `n8n execute --id ... --rawOutput`, in an isolated SQLite database.
- Replant v0.3.0, release binary built from code at `b1827d4`.
- Local `gemma4-e2b-heretic-Q4_K_M`, OpenAI-compatible HTTP API.
- **Manual Trigger**, **Set**, **Split Out**, **Loop Over Items** v3 (batch 1),
  **HTTP Request** v4.2, **Switch** v3 and **No Operation** nodes.
- 100 items per arm, one identical request repeated within each arm. Arm-specific
  contexts prevent an old record or the baseline from warming Replant's lookup.

The earlier measurements called the planner in Python. This test does not:
**the LLM request is a real n8n HTTP Request node inside the loop**. Python
orchestrates import/execution and independently inspects the result.

Baseline runs the model then `record` every iteration. Replant runs `lookup`
first: only `miss` reaches the model and `record`; `succeeded` continues the
loop. Any other status fails the verification. The model's JSON recipe is
parsed, not executed as code; optional Markdown fences are removed first.

Both arms used the same operator-owned tools and the unchanged 2,000 ms tool
deadline. The check log was verified entry by entry against actual counter
values, not just each receipt's self-reported status. The benchmark also checked
every final n8n loop item and the complete record/replay operation sequence.

LLM invocations and token totals come from n8n's `LLM Plan` execution data.
Every response must have positive usage telemetry. Node retries are disabled;
missing telemetry, a failed node or an incomplete loop fails the measurement.
Replant's `provider_calls: 0` is not used to count external inference.

## Reproduce

Use [`scripts/n8n_runtime_benchmark.py`](../scripts/n8n_runtime_benchmark.py) and
the [n8n setup instructions](../examples/n8n/README.md#actual-n8n-loop-with-a-live-model).
It saves both importable workflow JSON files, execution logs, state and
`report.json` in a new private directory. Do not run Python with `-O`: the script
uses assertions as verification gates.

The published generator was compared structurally against both workflow graphs
used in the 100-item measurement, excluding random node IDs. Its complete CLI
path was additionally run with two items per arm: the final reproduction smoke
used 871 vs 452 tokens, with two actual actions/checks per arm. Model response
length can vary; this smaller smoke run is not included in the 100-item table.

The host's existing n8n installation lacked its native SQLite binding. After
explicit operator approval, stock `sqlite3@5.1.7` was installed in an isolated
test directory and loaded into the test n8n process via `NODE_OPTIONS`. No
database behavior was mocked and no global n8n dependency was changed. The test
used no Code nodes and needed no external task-runner worker.

## Limits

- Real **CLI-mode n8n runtime**, not the stopped Docker/webhook deployment. The
  custom Replant community node was not part of this measurement.
- Exact-repeat fixture, not arbitrary loops with changing requests or context.
  Both model and independent checks are intentionally simple.
- The local provider reports prompt-cache tokens; totals include them. No paid
  invoice saving is asserted, and timings are one local run, not a general SLA.
- A hand-written fixed counter workflow can avoid inference altogether. This
  test measures bypassing repeated planning after a recipe is supplied once.
- No production workflow, credential, counter or Replant store was reused.
